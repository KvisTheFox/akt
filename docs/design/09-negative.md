# akt — жёсткие запреты и чек-лист ревью

Этот файл — единственное место, где собраны запреты. Если правило
синтаксиса нужно уточнить, оно живёт в
[`01-syntax.md`](01-syntax.md); здесь — только «нельзя» и почему.

---

## 1. Запреты языка

### 1.1. Синтаксис

| Запрещено | Почему | Правильно |
|---|---|---|
| `let x = 5` | `let` не существует | `i32 x = 5` или `auto x = 5` |
| `mut` | все локальные переменные изменяемы | `i32 x = 5` |
| `try { } catch { }` | исключений нет | `Result<T, E>` + `?` |
| `is` | проверка типа не нужна | `switch` по enum |
| `unsafe { }` | нет безопасного/небезопасного режима | `manual`/`*T` на C-границе |
| `macro`, `template` | нет препроцессора и метапрограммирования | generics + `const fn` |
| `->` | не используется | `fn f() T` |
| `use std::io` | `::` в модулях запрещён | `use std.io` |
| `std::io.read()` | `::` в путях запрещён | `std.io.read()` |
| `T[N]` | C-деклараторная путаница | `[T; N]` |
| `f<T>(x)` | конфликт с `<` | `f[T](x)` |
| `struct`/`enum`/`fn` внутри функции | нет вложенных объявлений | объявите на уровне модуля |
| позиционная инициализация struct | поля инициализируются по имени | `Vec2 { x: 1.0, y: 2.0 }` |
| `void x` | `void` — не значение | не объявляйте переменную |
| `null` для `^T` или `Option<T>` | разные модели | `^T` всегда валиден; `Option<T>` — `Some`/`None` |
| `#define`, `#include` | препроцессора нет | `cinclude <header.h>` |
| `;` в конце каждой строки | не требуется | `;` только для нескольких инструкций в строке |

`and`, `or`, `not` — словесные операторы, а не ключевые слова.
Использовать их как имена можно, но не рекомендуется.

`step` — контекстное слово только в `for`-диапазоне. `move` —
модификатор захвата замыкания. `volatile` — только квалификатор
указателя в C-привязках. `shared` — зарезервированный модификатор
памяти; в захвате замыкания используется он же.

### 1.2. Семантика

- **Нет сборщика мусора.** Ни в каком виде: ни Boehm GC, ни
  refcount-циклы «как GC», ни опционального GC.
- **Нет исключений.** Ошибки — значения `Result<T, E>`.
- **Нет наследования.** Только композиция и `impl`.
- **Нет приватных полей структуры.** Все поля публичны, если
  структура `pub`. Инкапсуляция — через методы и непрозрачные
  типы.
- **Нет неявных числовых повышений.** `i8 → i32`, `f32 → f64`
  запрещены. Только `as`.
- **Нет автоматического `string → cstring`.** Нужен
  `s.as_c_str()` или `std.c.cstring(s)`.
- **Нет `shared`-магии для данных.** `shared` делает атомарным
  только refcount. Гонки данных не проверяются.
- **Нет «умных» перегрузок по значению.** Только точное
  совпадение типов и fallback.
- **Нет «магических» методов** (`__init__`, `__add__`, операторы
  не перегружаются). Для операций есть именованные методы.

### 1.3. Память

| Запрещено | Почему |
|---|---|
| Ссылка `^T` на дочерний регион после его выхода | висячая ссылка |
| Возврат `^T` на локальную переменную | регион умрёт |
| Передача `auto`/`arena` в другой поток по ссылке | регион привязан к потоку |
| Цикл сильных `shared`-ссылок | утечка refcount |
| `manual` без `defer`/`free`/`close` | утечка ресурса |
| Использование `weak` без `upgrade()` | объект мог умереть |
| `arena_free` на вложенной арене из родителя | нарушение дерева регионов |
| Ручной `malloc` без явного освобождения | утечка |
| `defer` в цикле с накоплением ресурсов | отложенные вызовы копятся до выхода из scope |

`defer` не реализуется через `atexit`: на MSVC и в C99 fallback —
явный goto-cleanup. `atexit` не гарантирует порядок и не видит
локальные ресурсы.

### 1.4. Ошибки и паника

- **Ожидаемые ошибки — не паника.** Нет файла, нет прав, битый
  JSON, неверный аргумент — это `Result`.
- **Паника — только для нарушения инварианта.** Например,
  `assert` в тесте или невозможное состояние.
- **Нельзя игнорировать `Result`.** `must_use`-эквивалент:
  результат `Result`/`Option` обязан быть обработан.
- **Нельзя использовать `?` в функции без совместимого `Result`.**
- **Нельзя смешивать типы ошибок без явной конвертации.**
  `Err(string)` и `Err(Error)` — разные типы.
- **Нельзя возвращать `Ok(())` из функции с `Result<T, E>`, где
  `T != void`.**

### 1.5. Модули и сборка

- **Нет заголовочных файлов.** Файл = модуль.
- **Нет циклических импортов.** Граф модулей — DAG.
- **Нет `build.akt` и произвольных build-хуков.** Манифест
  `katek.toml` декларативен.
- **Нет плагинов сборки**, исполняющих произвольный код.
- **Нет `curl | sh` внутри сборки.** Сеть — только явные
  `katek fetch/update/add`.
- **Нет скачивания без lock-файла** в `--locked` режиме.
- **Нет недетерминированного порядка линковки.**
- **Нет `.cdr`.** Расширение исходников — только `.akt`.

При этом **разрешены** декларативные описания C-зависимостей:

```toml
[native]
providers = ["xrepo", "vcpkg", "cmake", "pkg-config", "system"]

[native.dependencies]
zlib = { provider = "xrepo", version = "1.3.1" }
sqlite3 = { provider = "cmake", package = "SQLite3", version = "3.45" }
```

Это не build-хук: `katek` сам вызывает провайдер, фиксирует
результат в `katek.lock` и передаёт include/lib/defines дальше.
Пользовательские скрипты и произвольные команды запрещены.

### 1.6. C-интероп

| Запрещено | Почему |
|---|---|
| Передавать замыкание с захватами как C-callback | нет C-совместимого контекста |
| Передавать `string` туда, где ждут `cstring` | нет NUL-гарантии |
| Хранить `cstring` после освобождения источника | висячий указатель |
| Возвращать `*T` на стековую переменную | висячий указатель |
| Игнорировать `null` от C-функции | падение |
| Использовать `...` вне `cfn` | нет variadic в akt-функциях |
| Полагаться на порядок полей `struct` в C | используйте `cstruct` |
| Смешивать `*T` и `^T` без явной границы | разные модели памяти |
| Ожидать, что C-код соблюдает проверки akt | C-граница не проверяется |

C-граница — это ответственность программиста. Компилятор
проверяет типы и ABI, но не валидность указателей из C.

## 2. Запреты в примерах и документации

Пример обязан компилироваться текущим `aktc` или быть явно
помечен как псевдокод. Запрещено:

1. **`// hello.cdr`** и любое упоминание `.cdr` как рабочего
   расширения. Только `.akt`.
2. **Код без `fn main` или модульного контекста**, если это
   заявлено как программа.
3. **Объявления `struct`/`enum`/`fn` внутри функции.**
4. **`T[N]`, `f<T>(...)`, `std::io`, `let`, `try`, `is`.**
5. **`?` в `fn main() int`** без обработки.
6. **`Ok(())` в функции, возвращающей `Result<T, E>` с `T != void`.**
7. **Использование std-модуля без `use` или feature-флага.**
8. **Примеры с гонками данных**, выдаваемые за корректные.
9. **`shared` как замена `Mutex`.**
10. **`cstring` из `string` без `.as_c_str()`.**
11. **Вложенные f-строки с неэкранированными кавычками**, если
    целевой парсер их не поддерживает. В akt поддерживаются:
    `f"name = {user["name"]}"`.
12. **Чат-артефакты** в документе: «Отправляю партиями»,
    «продолжай», «Конец сообщения N из M», внешние ```-обёртки.
13. **Ссылки на несуществующие файлы** (`00-philosophy.md` должен
    существовать, `10-prompts.md`, `11-roadmap.md`,
    `12-c-interop.md` — тоже).
14. **Несоответствие версии и `edition`** в манифесте.
15. **Придуманные API std**, которых нет в `05-stdlib.md`.

## 3. Чек-лист ревью кода

### 3.1. Синтаксис и типы

- [ ] Нет `let`, `mut`, `try`, `is`, `unsafe`, `macro`, `template`.
- [ ] Нет `::` для модулей; `::` только для enum и
      ассоциированных функций.
- [ ] Массивы — `[T; N]`, не `T[N]`.
- [ ] Явные generic-аргументы — `f[T](...)`.
- [ ] Нет вложенных `struct`/`enum`/`fn`/`test`.
- [ ] Нет неявных числовых преобразований; только `as`.
- [ ] Все `return` одного типа; рекурсия типизирована явно.
- [ ] `switch` покрывает все варианты или имеет `default`.

### 3.2. Память

- [ ] Нет `^T` на локальные значения, возвращаемые наружу.
- [ ] Нет `auto`/`arena` в другом потоке по ссылке.
- [ ] Нет циклов сильных `shared`.
- [ ] `weak` используется только с `upgrade()`.
- [ ] `manual` закрывается через `defer`/`free`/`close`.
- [ ] `arena` не передаётся и не возвращается.
- [ ] `defer` не используется для накопления ресурсов в цикле.

### 3.3. Ошибки

- [ ] Ожидаемые ошибки — `Result`, не `panic`.
- [ ] `Result`/`Option` не игнорируются.
- [ ] `?` только в функции с совместимым `Result`.
- [ ] `Ok(())` только для `Result<void, E>`.
- [ ] Типы ошибок не смешиваются без конвертации.
- [ ] `main`, возвращающий `int`, не использует `?`.

### 3.4. C-граница

- [ ] `cinclude`/`cfn`/`cstruct`/`cunion` соответствуют ABI.
- [ ] `string` → `cstring` только через `.as_c_str()`.
- [ ] C-callback без замыканий с захватами.
- [ ] `null` проверяется до разыменования.
- [ ] Владение `*T` задокументировано.
- [ ] Нет `...` вне `cfn`.

### 3.5. Сборка

- [ ] Зависимости объявлены в `katek.toml`, а не в скриптах.
- [ ] `katek.lock` закоммичен.
- [ ] Нет произвольных build-хуков.
- [ ] Нет `curl`/`wget` в build-командах.
- [ ] Версии C-зависимостей зафиксированы.
- [ ] `katek build --locked` проходит.

## 5. Как отклонять предложения

Предложение отклоняется, если оно:

1. **Добавляет GC** — даже опциональный, даже «только для
   удобства».
2. **Добавляет исключения** — даже как синтаксический сахар над
   `Result`.
3. **Добавляет макросы/препроцессор** — даже «безопасные».
4. **Добавляет наследование** — даже одиночное.
5. **Делает `shared` автоматически потокобезопасным** — это
   скрытая стоимость и ложная гарантия.
6. **Добавляет неявные преобразования** — особенно string ↔
   cstring и числовые повышения.
7. **Добавляет произвольные build-хуки** — вместо декларативных
   провайдеров.
8. **Требует внешний рантайм** для базового бинарника.
9. **Ломает C-совместимость ABI** без `cstruct`/`cfn`.
10. **Противоречит модели регионов** — например, «сборка мусора
    для cyclic shared».

Исключение: **декларативные** C-зависимости через xrepo, vcpkg,
Conan, CMake, pkg-config, `system`, `path`, `prebuilt` — это часть
дизайна, а не build-хук.

## 6. Красные флаги в промптах для ИИ

Если в задании встречается одно из этих слов, задание нужно
уточнить, а не выполнять буквально:

- «добавь GC»;
- «сделай как в Rust» (заимствования, lifetimes, traits);
- «сделай как в Python» (исключения, динамическая типизация);
- «добавь макросы»;
- «добавь build.akt»;
- «позволь `.cdr` для совместимости»;
- «пусть `shared` будет потокобезопасным»;
- «сделай `let` для иммутабельности»;
- «добавь `try/catch`»;
- «добавь автоматическое приведение string к cstring».

Правильный ответ в таких случаях — объяснить, какой механизм akt
уже решает задачу: регионы, `Result`, `Option`, `manual`,
декларативные провайдеры, `cinclude`/`cfn`.
